# 信贷意图识别模型测试用例生成

## Usage

当用户需要为**信贷场景下的意图识别模型**生成测试用例、评测数据集或测试策略时激活本 Skill。

适用场景：
- 信贷智能客服/对话机器人的意图分类模型测试
- 借款下单、账单、还款、额度、利率、提额、降息、增信补资料等金融NLP任务的评测集构建
- 意图混淆、边界case、对抗样本的测试设计

## Workflow

1. **明确意图体系**：确认标准意图分类体系（见Reference Resources）
2. **信贷领域标准会话问答知识学习**：标准知识文档详见making_decison_test/docs/standard_QA_intent.xlsx
3. **确定测试维度**：没割标准意图的核心拆分均需包含如下维度测试用例：
   - 标准表达（清晰明确的意图表述）
   - 同义变换（同义词、口语化、方言化表达）
   - 对抗/干扰（包含噪声、错别字、无关信息的表述）
3. **生成测试用例**：按如下要求的数量和测试维度进行用例生成，标注问题、期望意图和标准应答话术
   - 总用例数量400，各个标准意图占比如下
   - P0级：「转人工」占比15%、「风险合规禁答」占比15%
   - P1级：「提额降息」占比25%、「常规咨询」占比10%、「复合意图」占比5%、「借款下单」占比10%
   - P2级：「模糊意图」占比10%
   - P3级：「非业务相关意图」占比10%
4. **输出格式**：按固定格式输出，直接在指定目录下创建Excel文件保存
指定目录+文件名：making_decison_test/case_data/model_single_intent_test_cases.xlsx

## Output Format

每个测试用例必须包含以下字段：

| 字段     | 说明                               |
|--------|----------------------------------|
| 用例ID   | 格式：INTENT-{意图缩写}-{序号}，如 LOAN-001 |
| 类型     | single_turn                      |
| 测试意图   | 该用例对应的期望意图分类                     |
| 测试意图拆分 | 该用例对应的期望意图分类的核心拆分                |
| 场景     | 格式：{意图分类}-{核心拆分}-{标准问题}          |
| 测试维度   | 标准表达/同义变换/边界模糊/对抗干扰/负向样本         |
| 标准问题   | 用户模拟 query                       |
| 标准答案   | 模型针对标准问题输出的标准答案                  |
| 优先级    | P0（核心）/ P1（重要）/ P2（一般）/ P3（建议）   |
| 备注     | 特殊说明，如多意图标注、已知难点                 |

输出时先给**测试策略概述**，再按意图分组输出**测试用例表格**。

## Reference Resources

### 信贷意图标准分类体系
| 意图分类    | 核心拆分       | 定义说明                      |
  |---------|------------|---------------------------|
  | 提额降息    | 操作咨询       | 用户询问提额/降息的具体操作方式、条件、材料要求等 |
  | 提额降息    | 进度咨询       | 用户询问提额/降息审核进度、状态、结果通知等    |
  | 提额降息    | 定制诉求       | 用户明确提出具体的提额/降息目标数值        |
  | 常规咨询    | 额度咨询       | 用户咨询额度、征信、风控等额度评估相关问题     |
  | 常规咨询    | 定价咨询       | 用户咨询利率、费用、手续费等定价相关问题      |
  | 常规咨询    | 账单咨询       | 用户咨询账单、还款、合同等账务相关问题       |
  | 常规咨询    | 其他咨询       | 其他常规咨询问题，如客服时间、系统提示等      |
  | 复合意图    | 提额+降息      | 用户一句话同时包含提额和降息两个意图        |
 | 复合意图    | 提额+下单      | 用户一句话同时包含提额和下单借款两个意图      |
  | 转人工     | 标准诉求       | 用户明确要求转接人工客服              |
  | 转人工     | 情绪升级       | 用户表达不满情绪，要求转接人工客服         |
  | 借款下单    | 借款操作       | 用户询问如何借款、下单的操作流程          |
  | 借款下单    | 借款咨询       | 用户咨询借款金额、借款条件、借款失败原因等     |
  | 模糊意图    | 口语化/关键信息缺失 | 用户问题过于口语化或缺少关键业务信息        |
  | 非业务相关意图 | 闲聊/非信贷意图   | 用户问题与信贷业务无关，属于闲聊范畴        |
  | 风险合规禁答  | 违规操作       | 用户涉及套现、伪造材料、威胁等违规操作       |
  | 风险合规禁答  | 内部信息探知     | 用户探知公司内部信息，如风控系统、领导电话等    |
  | 风险合规禁答  | 合规边界       | 用户涉及未成年人借款等合规边界问题         |

### 信贷意图标准分类优先级排序
- P0：「转人工」、「风险合规禁答」
- P1：「提额降息」、「常规咨询」、「复合意图」、「借款下单」
- P2：「模糊意图」
- P3：「非业务相关意图」

### 测试维度定义

| 维度 | 定义 |
|------|------|
| 标准表达 | 使用业务标准术语，意图明确无歧义 |
| 同义变换 | 使用同义词、近义词、口语化、方言化表达同一意图 |
| 对抗干扰 | 包含错别字、噪声、无关信息、长冗余表述 |

## Rules

1. **意图标签标准化**：输出的意图标签必须与用户确认的意图体系一致，不得自行创造新标签。
2. **多意图处理**：当输入文本包含多个意图时，标注**主意图**，并在备注中说明次意图。
3. **口语化真实**：同义变换和对抗干扰维度的输入文本必须贴近真实用户表达，避免过于书面化。
4. **数量控制**：针对指定意图的单个核心拆分，生成用例在不同测试维度的占比：40%标准表达，30%同义变换，30%对抗干扰


## Supplementary Knowledge

**信贷意图识别常见难点：**
- 「查询额度」与「查询利率」常因用户同时询问而混淆
- 「提前还款」与「还款方式」在口语中边界模糊（如"我想换个方式还款"可能被误判为提前还款）
- 用户常使用反问句表达意图（如"我不能提前还吗？"）容易被识别为闲聊或投诉
- 方言和口语填充词（"那个"、"就是"、"啊"）对模型干扰较大
- 不同用户因为自身条件不一样，同一个问题可能会有两种不同的答案

**信贷合规边界：**
- 禁止向未成年人提供服务
- 个人额度上限20万，不能超出
- 个人定价/利率上限为24（25年10月前上限为36，需要注意该时间节点）
- 不能向用户做出额度、利息和借款金额的承诺

**提额/降息支持的资料上传项：**
- 支付宝/微信账单截图
- 银行流水截图
- 个人公积金认证
- 个人信用分认证
- 个税认证
