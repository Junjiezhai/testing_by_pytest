# 贷后催收意图识别模型测试用例生成

## Usage

当用户需要为**贷后催收场景下的意图识别模型**生成测试用例、评测数据集或测试策略时激活本 Skill。

适用场景：
- 贷后催收智能客服/对话机器人的意图分类模型测试
- 逾期协商、还款减免、停催/缓催、还款咨询等贷后核心意图的评测集构建
- 意图混淆、边界case、对抗样本的测试设计（如「投诉类」与「泛协商」的边界）
- 风险合规禁答场景（违规操作、信息探知）的合规性测试

## Workflow

1. **明确意图体系**：确认贷后催收标准意图分类体系（详见 `making_decison_test/docs/postloan_intent_taxonomy.md`）
2. **信贷领域标准会话问答知识学习**：标准知识文档详见 `making_decison_test/docs/postloan_ref_QA_intent.md`
3. **确定测试维度**：每个标准意图的核心拆分均需包含如下维度测试用例：
   - 标准表达（清晰明确的意图表述）
   - 同义变换（同义词、口语化、方言化表达）
   - 对抗/干扰（包含噪声、错别字、无关信息的表述）
3. **生成测试用例**：按如下要求的数量和测试维度进行用例生成，标注问题、期望意图和标准应答话术
   - 总用例数量400，各个标准意图占比如下
   - P0级：「转人工」占比20%、「风险合规禁答」占比20%
   - P1级：「贷后协商」占比20%、「贷后咨询」占比15%
   - P2级：「非贷后咨询」占比15%
   - P3级：「未知意图」占比10%
5. **输出格式**：按固定格式输出，直接在指定目录下创建 Excel 文件保存
   指定目录+文件名：`making_decison_test/case_data/postloan_single_intent_test_cases.xlsx`

## Output Format

每个测试用例必须包含以下字段：

| 字段     | 说明                               |
|--------|----------------------------------|
| 用例ID   | 格式：INTENT-{意图缩写}-{序号}，如 LOAN-001 |
| 类型     | single_turn                      |
| 测试意图   | 该用例对应的期望意图分类                     |
| 测试意图拆分 | 该用例对应的期望意图分类的核心拆分                |
| 场景     | 格式：{意图分类}-{核心拆分}-{标准问题}          |
| 测试维度   | 标准表达/同义变换/边界模糊/对抗干扰/负向样本         |
| 标准问题   | 用户模拟 query                       |
| 标准答案   | 模型针对标准问题输出的标准答案                  |
| 优先级    | P0（核心）/ P1（重要）/ P2（一般）/ P3（建议）   |
| 备注     | 特殊说明，如多意图标注、已知难点                 |

输出时先给**测试策略概述**，再按意图分组输出**测试用例表格**。

## Reference Resources

### 贷后催收意图标准分类体系

| 意图分类 | 核心拆分 | 定义说明 |
|---------|---------|---------|
| 风险合规禁答 | 违规操作 | 用户试图要求平台做违规操作，如不上报征信、篡改信息等。AI 机器人需识别并拒绝响应 |
| 风险合规禁答 | 信息探知 | 用户试图探知平台内部敏感信息，如催收策略、内部员工个人信息、三方联系人信息等。AI 机器人需识别并拒绝响应 |
| 转人工 | 标准诉求 | 用户明确要求转接人工客服或专员处理 |
| 转人工 | 投诉类 | 用户明确投诉催收行为、隐私泄露、暴力催收等，需立即转人工紧急处理 |
| 贷后协商 | 还款减免 | 用户请求减免费用或只还本金。属于催收减免服务（有还款能力，希望结清出催） |
| 贷后协商 | 还款减压 | 用户请求延期、停催、缓催。属于还款减压服务（无还款能力，有还款意愿，希望停止催收延期还款） |
| 贷后协商 | 协商还 | 用户明确提出协商还款方案。属于协商还款服务（有一定还款能力，有还款意愿，重新制定还款计划） |
| 贷后协商 | 泛协商 | 用户表达还款困难但未明确具体协商诉求，需要进一步引导确认 |
| 贷后咨询 | 还款咨询 | 用户咨询还款方式、金额、时间、提前还款等贷后还款相关问题 |
| 贷后咨询 | 征信咨询 | 用户咨询征信查询、上报、逾期影响等征信相关问题 |
| 非贷后咨询 | 退款咨询 | 用户咨询退款、退费相关问题 |
| 非贷后咨询 | 借款额度咨询 | 用户咨询借款额度、开通额度等借款前相关问题 |
| 非贷后咨询 | 账户咨询 | 用户咨询账户管理、解绑、修改信息等操作问题 |
| 非贷后咨询 | 其他咨询 | 其他不属于上述类别的非贷后问题（费用、扣费等） |
| 未知意图 | 模糊意图 | 用户意图不明确，无法确定具体业务诉求，需要进一步引导 |
| 未知意图 | 闲聊 | 用户表达感谢、告别、简短问候等，无实质业务诉求 |

### 贷后催收意图标准分类优先级排序
- P0：「转人工」、「风险合规禁答」
- P1：「贷后协商」、「贷后咨询」
- P2：「非贷后咨询」
- P3：「未知意图」

### 测试维度定义

| 维度 | 定义 |
|------|------|
| 标准表达 | 使用业务标准术语，意图明确无歧义 |
| 同义变换 | 使用同义词、近义词、口语化、方言化表达同一意图 |
| 对抗干扰 | 包含错别字、噪声、无关信息、长冗余表述 |

### 关键边界 case（人工复核重点关注的易混淆场景）

1. **「投诉类」与「未知意图-模糊意图」的边界**：用户虽然表达不满（如"你们怎么又打电话"），但没有明确投诉意图时，应归为「未知意图-模糊意图」而非「转人工-投诉类」
2. **「信息探知」与「账户咨询」的边界**：用户咨询专员号码、内部流程等敏感信息时，应归「风险合规禁答-信息探知」；咨询账户操作（解绑、修改密码）时归「非贷后咨询-账户咨询」
3. **「违规操作」与「贷后咨询」的边界**：用户问"能不能不上征信"属于试图要求违规操作，归「风险合规禁答-违规操作」；用户问"逾期多久上征信"属于正常咨询，归「贷后咨询-征信咨询」
4. **「泛协商」与「未知意图-模糊意图」的边界**：用户明确表达"还不上""困难"等还款困难时归「贷后协商-泛协商」；用户仅说"最近比较麻烦"等模糊表达时归「未知意图-模糊意图」

## Rules

1. **意图标签标准化**：输出的意图标签必须与用户确认的意图体系一致，不得自行创造新标签。
2. **多意图处理**：当输入文本包含多个意图时，标注**主意图**，并在备注中说明次意图。
3. **口语化真实**：同义变换和对抗干扰维度的输入文本必须贴近真实用户表达，避免过于书面化。
4. **数量控制**：针对指定意图的单个核心拆分，生成用例在不同测试维度的占比：40%标准表达，30%同义变换，30%对抗干扰


## Supplementary Knowledge

**贷后催收意图识别常见难点：**
- 「还款减压」与「协商还款」业务的边界是用户是否具有一定的还款能力，如果没有上下文背景，常常容易混淆
- 用户常会倾诉自身遇到的困境，潜在表达就是没有能力进行还款，要适当引导协商还款
- 用户情绪升级常常是因为催收方式过于频繁，包含短信、电话和通知身边亲属等，用户的真是诉求是停催，很容易被模型忽视，应对方式应该是引导协商还款
- 用户自身情绪升级，出现威胁、恐吓或者投诉等激烈对抗话术，需要引导转人工
- 用户常会担忧协商后会再次出现催收行为，需要跟用户阐明停催之后再次触发催收的规则，比如用户违约跳票等，缓解用户焦虑
- 风险合规禁答：「信息探知」主要指用户通过话术打探公司内部信息，包含催收策略、内部员工个人信息、以及公司内部记录的三方联系人信息（亲属/朋友等）
- 风险合规禁答：「违规操作」主要指用户通过诱导话术、贿赂、虚假承诺等帮助篡改信息，或调整催收策略等等

**贷后催收应答话术合规边界：**
- 禁止使用侮辱/辱骂、威胁、恐吓、曝光、报警等高风险表达
- 禁止诱导或暗示用户借新还旧
- 针对情绪极端用户，需要注意语气和话术安抚，禁止激怒用户做伤害自己/他人/社会的事
- 禁止向用户提供合规业务之外的服务
- 不得引导用户进行私下交易、或通过第三方渠道联系
- 不得泄露用户隐私（包含个人信息、三方联系人信息等）
- "停催"是不合规表达，模型答复中需要替换成"人工提醒服务"

**贷后催收提供的合规服务项及说明：**

  | 服务项      | 用户核心诉求 | 针对客群                  | 完整说明                                                                      |
  |----------|--------|-----------------------|---------------------------------------------------------------------------|
  | 催收减免     | 出催     | 有还款能力，无还款意愿，希望结清账单出催  | 减免用户部分还款金额，降低用户还款难度，促进用户还款的服务（减免金额由策略规则计算得出）                              |
  | 还款减压/轻松还 | 停催     | 无还款能力，有还款意愿，希望停止催收，延期还款 | 为用户减轻还款压力，重新制定新的还款计划，用户按新的还款计划进行还款，如果未按期还款，以新的还款计划进行催收                    |
  | 协商还款     | 停催     | 有一定的还款能力，有还款意愿，希望停止催收，延期还款 | 跟用户协商，在用户完成部分还款后，制定新的还款计划，用户承诺还款，分期乐停止催收，缓解用户还款压力，用户如果违约跳票，则按旧的还款计划恢复催收 |


**贷后催收专业术语及说明：**
- 逾期用户：也称为案件，一个案件表示一个逾期用户；
- 入催：用户逾期后，交易中台会将用户逾期的账单通过SFTP同步到催收系统；
- 停催：停止针对逾期用户进行催收触发的行为叫做停催，包含打电话、发短信等；
- 出催：用户还完逾期欠款，未逾期后出催（催收系统未激活的案件）；
- 内催：分期乐内部催收的案件；
- 委外：特指委外公司催收的案件；
- 结清: 用户还完所有的账单；
- 逾期计算：贷后催收是基于用户渠道维度，需要将用户的所有账单金额按照渠道来汇总计算用户在不同渠道的逾期金额，在贷金额；
- 分单：特指将用户分配到不同的催收队列；
- 委案：将案件委派给催收公司；
- 退案：同撤案、召回，将催收公司的案件收回（分期乐）；
- 留案申请: 在案件退案时间之前，催收公司可以申请留案，委案延期；
- 派件：案件分配给催员；
- 下P：案件状态调整为承诺还款；
- 违约跳票：承诺还款期限内未还款；
- 入账：用户在分期后，会生成12、24、36期账单，然后逐月进行还款，还款完成后对应的账单就需要进行入账操作，实际就是将未还账单调整为已还款。
- 还款: 用户还钱；
- 代扣：与用户签订代扣协议，允许在后台对银行卡进行自动扣款的功能。当代扣成功仍需通过一定的功能将扣到的金额分配至用户的账单，进行入账。
- 减免: 减免功能，给uid的账单进行减免，达到降低账单应还金额的目的。催收侧通过代码控制减免额度的分配逻辑，将总减免金额分配至每笔账单，之后批量调用中台减免接口。有常规减免、政策性减免、反欺诈减免三种减免类型。
- 对公：线下收款后，线上调用交易接口入账，目前有个人对公，和公对公两种；
- 外呼: 给用户打电话；
- 手呼：催员手动拨号；
- 自动外呼：组长统一安排群呼，拨打队列下的所有案件，自动分配给置闲的催员；
- 巡航外呼：催员批量外呼自己名下的所有案件；
- 工作手机: 催员使用特殊厂商定制的功能机，方便携带，可随时外呼，短信；
- 短信：给用户发送短信消息；
- 机构: 特指委外机构，催收公司；
- IB：特指用户来电（用户致电贷后客服）；
- 律师函：特指给用户发送电子律师函；
- 质检：特指质检员，约束催员合规催收；
