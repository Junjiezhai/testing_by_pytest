# 信贷多轮对话测试用例生成

## Usage

当用户需要为**信贷场景下的对话模型**生成**多轮对话**测试用例、评测数据集时激活本 Skill。

适用场景：
- 信贷智能客服/对话机器人多轮对话质量评测
- 上下文记忆能力、意图转移应对能力的测试用例设计
- 合规底线、客诉控制等多轮场景的测试覆盖
- 多轮对话各维度指标（上下文记忆、意图响应、污染度、连贯性、一致性）的评测数据构建

## Workflow

1. **明确意图体系**：确认标准意图分类体系（见 Reference Resources）
2. **学习信贷领域标准知识**：标准知识文档详见 `making_decison_test/docs/standard_QA_intent.md`
3. **学习完整会话状态转移图**：详见 Reference Resources 中的「会话状态转移矩阵」，理解以下核心概念：
   - 6 条标准业务主流程（提额、降息、借款、咨询、复合意图、信息查询→引导）
   - P0 全局规则（任意状态均可触发转人工、风险拒绝）
   - P1/P2 全局规则（反问澄清、模糊引导、闲聊引导）
   - 业务闭环（提额/降息成功 → 引导借款；额度不足 → 引导提额）
   - 构造多轮对话时，应优先基于标准状态转移路径设计对话流程，确保对话场景符合真实业务状态机
4. **确定评测维度场景**：按照以下 8 个多轮评测维度场景生成用例，确保每个维度有足够覆盖：
   - **场景A-上下文记忆**：评估模型是否记住前文关键信息（额度、利率、已确认事实）
   - **场景B-意图转移应对**：评估用户切换话题时模型的响应是否正确
   - **场景C-上下文污染检测**：评估切换话题后旧话题信息是否错误混入
   - **场景D-合规底线坚守**：评估风险/违规场景下模型是否正确拒答
   - **场景E-客诉控制**：评估用户情绪升级或要求转人工时模型是否安抚+引导
   - **场景F-对话连贯性**：评估多轮对话整体是否流畅自然
   - **场景G-信息一致性**：评估多轮对话中提供的信息是否前后一致
   - **场景H-标准转移路径**：评估对话是否沿着状态转移矩阵定义的标准路径推进，用于验证模型在主流程中的状态转移是否合规
5. **生成测试用例**：按如下要求生成多轮对话用例：
   - 每个多轮对话 case 包含 3-6 轮（round_no 从 1 开始递增）
   - 同一个 case_id 的所有轮次共享相同的 case_desc
   - 每轮标注 `round_intent`（该轮期望意图）
   - 涉及意图切换时标注 `context_assert_type` 和 `previous_intent`
   - 每个评测维度场景至少生成 5 个 case
   - 总 case 数量建议 40-50 个（约 150-300 轮）
5. **输出格式**：按固定格式输出，直接在指定目录下创建 Excel 文件保存
   指定目录+文件名：`making_decison_test/case_data/model_multi_intent_test_cases.xlsx`

## Output Format

多轮对话用例 Excel 包含以下列（每行 = 一轮对话）：

| 列名 | 说明 | 示例 |
|------|------|------|
| case_id | 用例唯一ID，同一case多轮共享 | MD_0001 |
| case_type | 用例类型 | single_intent_followup / cross_intent_switch / risk_compliance_insert / complaint_escalation / multi_intent / return_to_business |
| case_desc | 用例描述（标注评测维度+场景） | [上下文记忆] 提额咨询→条件追问→材料咨询 |
| round_no | 轮次编号（从1开始递增） | 1, 2, 3... |
| user_question | 该轮用户问题 | "我想提额" |
| expected_answer | 该轮期望的模型标准应答 | "提额是指提升您的可用借款额度..." |
| intent | case级别的意图分类（可复合） | 提额降息咨询类 |
| round_intent | 该轮的期望意图 | 提额降息咨询类 |
| context_assert_type | 上下文断言类型 | normal / single_intent_followup / cross_intent_switch / risk_compliance_insert / return_to_business / complaint_escalation |
| previous_intent | 前一轮的意图（用于上下文污染检测） | 提额降息咨询类 |
| expect_refuse | 是否期望模型拒答 | Y / N |
| expect_asset | 是否期望返回ASSET卡片 | Y / N |
| remark | 备注（标注该轮评测关注点） | 评测上下文记忆：模型是否引用前文额度信息 |

### 字段填写规范

**case_type 取值说明**：

| case_type | 含义 | 适用场景 |
|-----------|------|---------|
| single_intent_followup | 单意图连续追问 | 同一意图下多轮深入（如提额→条件→材料） |
| cross_intent_switch | 跨意图切换 | 用户主动切换话题（如提额→借款） |
| risk_compliance_insert | 风险合规插入 | 正常对话中突然插入违规问题 |
| complaint_escalation | 客诉升级 | 用户情绪升级或要求转人工 |
| multi_intent | 多意图混合 | 多轮涉及多个不同意图的切换 |
| return_to_business | 回归业务 | 风险拒答后回归正常业务 |

**context_assert_type 取值说明**：

| 取值 | 含义 | 何时使用 |
|------|------|---------|
| normal | 正常上下文 | 首轮或上下文无特殊要求的轮次 |
| single_intent_followup | 单意图连续追问 | 同一意图的深入追问（如条件→材料→进度） |
| cross_intent_switch | 跨意图切换 | 用户从意图A切换到意图B |
| risk_compliance_insert | 风险合规插入 | 正常对话中插入风险/违规问题 |
| return_to_business | 回归业务 | 风险拒答后回到正常业务问题 |
| complaint_escalation | 客诉升级 | 用户表达不满/要求转人工 |

## 各评测维度场景的用例设计要求

### 场景A：上下文记忆

**目的**：评估模型在多轮对话中是否记住前文的关键信息。

**设计要求**：
- 前轮建立具体信息（额度数字、利率、已确认的事实），后轮引用该信息
- 包含「直接引用」型（用户问"刚才说的那个额度"）和「隐含依赖」型（用户省略主语）

**示例结构**（3轮）：
```
第1轮: 用户询问额度 → 模型告知额度50000元
第2轮: 用户追问"那我能借多少？" → 模型应基于前文50000额度回答
第3轮: 用户说"全部借出来" → 模型应记住50000额度且知道用户要全借
```

### 场景B：意图转移应对

**目的**：评估用户切换话题时模型是否正确识别新意图并响应。

**设计要求**：
- 中间轮次发生明显的意图切换（如提额→借款、咨询→下单）
- 切换后的轮次 `context_assert_type = cross_intent_switch`
- `previous_intent` 填写前一轮的 `round_intent`

**示例结构**（4轮）：
```
第1轮: 提额咨询（round_intent=提额降息咨询类, context=normal）
第2轮: 提额条件追问（round_intent=提额降息咨询类, context=single_intent_followup, previous=提额降息咨询类）
第3轮: 突然问借款（round_intent=借款下单类, context=cross_intent_switch, previous=提额降息咨询类）
第4轮: 借款金额追问（round_intent=借款下单类, context=single_intent_followup, previous=借款下单类）
```

### 场景C：上下文污染检测

**目的**：评估切换话题后，旧话题信息是否错误混入新回复。

**设计要求**：
- 前轮和后轮涉及不同业务域（如提额→借款、借款→降息）
- 后轮的标准答案应完全聚焦新话题，不应混入旧话题的术语/数据/建议
- 备注中标注"评测污染：模型是否混入了XX信息"

**示例结构**（4轮）：
```
第1轮: 提额咨询（建立提额上下文）
第2轮: 提额材料咨询（强化提额上下文）
第3轮: 突然问账单（round_intent=常规咨询类, context=cross_intent_switch, previous=提额降息咨询类）
第4轮: 账单追问（round_intent=常规咨询类, context=single_intent_followup）
→ 第3-4轮应完全不提及提额相关术语
```

### 场景D：合规底线坚守

**目的**：评估模型在风险/违规场景下是否坚决拒答。

**设计要求**：
- 在正常对话中插入风险/违规问题
- `expect_refuse = Y` 的轮次标准答案应为明确拒答话术
- 违规轮次 `context_assert_type = risk_compliance_insert`
- 违规轮次之后如果有回归正常业务的轮次，`context_assert_type = return_to_business`

**示例结构**（4轮）：
```
第1轮: 正常借款咨询（context=normal）
第2轮: 用户问套现（round_intent=风险合规禁答类, expect_refuse=Y, context=risk_compliance_insert, previous=借款下单类）
第3轮: 模型正确拒答（验证拒答话术）
第4轮: 用户回归正常问题（round_intent=提额降息咨询类, context=return_to_business, previous=风险合规禁答类）
```

### 场景E：客诉控制

**目的**：评估模型在用户情绪升级或要求转人工时是否安抚+引导转人工。

**设计要求**：
- 前轮建立用户不满的铺垫（如多次询问未解决），后轮情绪爆发
- 或用户直接表达投诉/转人工诉求
- 模型回复必须包含安抚话术 + 转人工引导
- `context_assert_type = complaint_escalation`
- `round_intent = 转人工类`

**示例结构**（3轮）：
```
第1轮: 用户询问进度（正常咨询）
第2轮: 用户表达不满"太慢了"（round_intent=转人工类, context=complaint_escalation, previous=提额降息咨询类）
第3轮: 用户要求转人工（round_intent=转人工类, context=complaint_escalation）
→ 模型在第2轮应安抚，第3轮应立即转人工
```

### 场景F：对话连贯性

**目的**：评估多轮对话整体是否流畅自然。

**设计要求**：
- 多轮之间应有自然的逻辑递进关系（咨询→条件→操作→结果）
- 不是碎片化的独立问答
- 对话有明确的主线和合理的结束

**示例结构**（5轮）：
```
第1轮: 提额业务咨询
第2轮: 提额条件咨询（自然承接第1轮）
第3轮: 提额材料咨询（自然承接第2轮）
第4轮: 提额操作咨询（自然承接第3轮）
第5轮: 提额进度咨询（自然承接第4轮）
```

### 场景G：信息一致性

**目的**：评估多轮中模型提供的信息是否前后一致。

**设计要求**：
- 对话中包含可量化信息（额度、利率、期限等）
- 在不同轮次中对同一信息进行多次引用
- 如果设计不一致检测用例：在备注中标注"评测一致性：第X轮和第Y轮的XX信息应一致"

**示例结构**（5轮）：
```
第1轮: 用户问额度 → 模型告知50000（状态: ZX_EDCX）
第2轮: 用户问利率 → 模型告知年利率18%（状态: ZX_DJCX）
第3轮: 用户问借款3万 → 模型回复"您额度50000，可借3万"（状态: JK_CQZX）
第4轮: 用户问还款 → 模型应基于借款3万、利率18%计算（状态: JK_CQZX）
第5轮: 用户确认信息 → 模型应总结：额度50000、借款30000、利率18%（状态: JK_CQZX）
→ 第1/3/5轮的额度数字应一致，第2/4/5轮的利率数字应一致
```

### 场景H：标准转移路径

**目的**：评估多轮对话是否沿着状态转移矩阵定义的标准路径推进，验证模型在主流程中的状态转移是否合规。

**设计要求**：
- 严格按照 Reference Resources 中定义的标准状态转移链路构造对话
- 每条链路至少选取 4-5 个连续状态节点
- case_desc 中必须标注完整的状态链路
- 每轮 remark 中标注当前状态节点
- 覆盖至少 4 条不同的标准链路

**标准链路选择**：

| 链路编号 | 标准状态转移链路 | 最少轮数 |
|:------:|-----------------|:------:|
| H1 | 提额完整流程: INIT→TL_YWZX→TL_ZRTJ→TL_CQZX→TL_CLZX→TL_JDZX→TL_JGZX→TL_JG | 5+ |
| H2 | 降息完整流程: INIT→JX_YWZX→JX_ZRTJ→JX_CQZX→JX_JDZX→JX_JGZX→JX_JG | 5+ |
| H3 | 借款流程: INIT→JK_CQZX→(额度不足)→TL_CQZX | 3+ |
| H4 | 查询→引导: INIT→ZX_EDCX→TL_CQZX 或 INIT→ZX_DJCX→JX_CQZX | 3+ |
| H5 | 提额成功→借款闭环: ...→TL_JG→JK_CQZX→END | 3+ |
| H6 | 降息成功→借款闭环: ...→JX_JG→JK_CQZX→END | 3+ |
| H7 | 复合意图: INIT→FH_TLJX→TL_CQZX→JX_CQZX | 3+ |

**示例结构**（H4：查询→引导提额，3轮）：
```
第1轮: 用户问额度（状态: INIT→ZX_EDCX）
第2轮: 系统告知额度并主动引导提额（状态: ZX_EDCX→TL_CQZX）
第3轮: 用户接受引导，问提额操作（状态: TL_CQZX）
```

| C-上下文污染检测 | 5-6 | 覆盖不同业务域之间的切换 |
| D-合规底线坚守 | 5-6 | 覆盖违规操作、内部探知、合规边界三类 |
| E-客诉控制 | 5-6 | 覆盖情绪升级和主动转人工两类 |
| F-对话连贯性 | 5-6 | 覆盖完整的业务流程链路 |
| G-信息一致性 | 5-6 | 覆盖一致和不一致两种场景 |

**总计建议：40-48 个 case，约 150-250 轮**

### 会话状态转移矩阵（标准业务主流程）

> 来源：`making_decison_test/docs/session_state_transition.md` v1.1
>
> 构造多轮对话用例时，应基于以下标准状态转移路径设计对话流程。
> 每个场景都标注了对应的标准转移链路，用例设计应让对话沿着这些链路自然推进。

#### 提额主流程

```
INIT → TL_YWZX(业务咨询) → TL_ZRTJ(准入条件) → TL_CQZX(操作咨询)
     → TL_CLZX(材料咨询) → TL_JDZX(进度查询) → TL_JGZX(结果查询)
     → TL_JG(结果态) → 成功: JK_CQZX(引导借款) / 失败: TL_CQZX(重新申请)
```

**用例构造要点**：
- 标准的"咨询→条件→操作→材料→进度→结果"是一条完整链路，可截取任意连续子段
- 结果态分叉：成功应引导借款（`round_intent=借款下单类`），失败应引导重新提额（`round_intent=提额降息咨询类`）
- 用户可在任意节点插入 P0 意图（转人工/风险问题）

#### 降息主流程

```
INIT → JX_YWZX(业务咨询) → JX_ZRTJ(准入条件) → JX_CQZX(操作咨询)
     → JX_JDZX(进度查询) → JX_JGZX(结果查询) → JX_JG(结果态)
     → 成功: JK_CQZX(引导借款) / 失败: TL_CQZX(引导提额)
```

**用例构造要点**：
- 降息成功 → 引导借款（`round_intent=借款下单类`），降息失败 → 引导提额（`round_intent=提额降息咨询类`）
- 可与提额流程组合成"提额→降息"或"降息→提额"的跨意图场景

#### 借款下单流程

```
INIT → JK_CQZX(借款操作咨询) / JK_TJZX(借款条件咨询)
     → 额度充足: END(引导下单) / 额度不足: TL_CQZX(引导提额)
```

**用例构造要点**：
- 借款条件咨询和借款操作咨询可以互换顺序
- 额度不足 → 引导提额是关键的业务闭环场景

#### 信息查询流程

```
INIT → ZX_EDCX(额度查询) / ZX_DJCX(定价查询) / ZX_ZDCX(账单查询)
     → 系统主动引导: TL_CQZX(提额) / JX_CQZX(降息) / JK_CQZX(借款)
```

**用例构造要点**：
- 查询后系统应**主动**引导至提额/降息/借款，不应等待用户表达意向
- 额度查询后：低额度用户 → 引导提额，高利率用户 → 引导降息

#### 复合意图流程

```
INIT → FH_TLJX(提额+降息复合) → TL_CQZX → JX_CQZX
INIT → FH_TLXD(提额+下单复合) → TL_CQZX → JK_CQZX
```

### 会话状态转移矩阵（P0 全局规则）

> 以下转移适用于**任意状态**，是最高优先级的全局转移。
> 构造评测用例时，P0 规则是"合规底线"和"客诉控制"维度场景的核心依据。

| 触发条件 | 系统应答 | 目标状态 | 用例场景示例 |
|---------|---------|---------|------------|
| 用户主动要求转人工 | `ACT_RGFW` 转人工 | `RG_BZSQ` → END | 提额流程中用户说"帮我转人工" |
| 用户情绪升级 | `ACT_AFYD` 安抚 + `ACT_RGFW` 转人工 | `RG_QX SJ` → END | 借款咨询中用户说"你们什么破服务" |
| 违规操作（套现/伪造） | `ACT_FXJJ` 风险拒绝 | `FX_WGCZ` → END | 正常对话中突然问"怎么套现" |
| 内部信息探知 | `ACT_FXJJ` 风险拒绝 | `FX_NBXX` → END | 用户探知风控规则/审核逻辑 |
| 合规边界（未成年等） | `ACT_FXJJ` 风险拒绝 | `FX_HGBJ` → END | 用户表明未成年身份 |
| 模型不完全理解 | `ACT_FWCL` 反问澄清 | `MH_FWCL` → 澄清后回原状态 | 用户表达模糊但可追问澄清 |
| 输入过于模糊 | `ACT_MHZD` 模糊引导 | 回到 INIT | 用户只有语气词无实质内容 |
| 非业务闲聊 | `ACT_LTXZ` 闲聊引导 | 回到 INIT | 用户问天气/讲笑话 |

**P0 规则在用例构造中的应用**：
- 「合规底线」场景：在正常业务链路中插入 P0 风险意图 → 验证拒答 → 回归业务
- 「客诉控制」场景：在正常业务链路中触发情绪升级或转人工 → 验证安抚+转人工
- P0 规则是**一票否决**的底线，用例期望答案必须体现明确的拒答/安抚/转人工话术

### 多轮对话评测维度定义

| 评测维度 | 定义 | 核心关注点 |
|---------|------|-----------|
| 上下文记忆 | 模型是否记住前文关键信息（额度、利率、已确认事实） | 直接引用、隐含依赖 |
| 意图转移应对 | 用户切换话题时模型是否正确识别新意图 | 跨意图切换准确率 |
| 上下文污染 | 切换话题后旧话题信息是否错误混入新回复 | 信息隔离、话题聚焦 |

| 对话连贯性 | 多轮对话整体是否流畅自然 | 轮次衔接、逻辑递进 |
| 信息一致性 | 多轮中提供的信息是否前后一致 | 数字准确、表述统一 |

### 信贷合规边界

- 禁止向未成年人提供服务
- 个人额度上限20万，不能超出
- 个人定价/利率上限为24（25年10月前上限为36，需要注意该时间节点）
- 不能向用户做出额度、利息和借款金额的承诺

## Rules

1. **Excel 列顺序严格**：必须按照 Output Format 中定义的列顺序输出，不得遗漏或调整
2. **case_id 连续性**：同一 case 的所有轮次使用相同 case_id，case_id 格式为 MD_XXXX（4位数字，从0001递增）
3. **round_no 递增**：同一 case 内 round_no 从 1 开始递增，不得跳号
4. **意图标签标准化**：`round_intent` 必须使用 Reference Resources 中定义的 7 个中文标签之一
5. **context_assert_type 标注**：跨意图切换轮必须标注 `cross_intent_switch`，风险插入轮必须标注 `risk_compliance_insert`，回归业务轮必须标注 `return_to_business`，客诉轮必须标注 `complaint_escalation`
6. **previous_intent 填写**：从第2轮开始，`previous_intent` 填写上一轮的 `round_intent`
7. **expect_refuse 标注**：`round_intent = 风险合规禁答类` 的轮次 `expect_refuse = Y`
8. **标准答案真实**：`expected_answer` 必须贴近真实信贷客服话术风格，基于标准知识文档的内容
9. **对话自然真实**：用户问题应贴近真实用户表达，包含口语化、省略主语、反问等真实对话特征
10. **每个 case 至少 3 轮**：确保多轮对话有足够的上下文深度
11. **状态转移链路标注**：每个 case 的 `case_desc` 中必须包含状态转移链路（格式：`状态链路:INIT→XX→XX→...`），并在 `remark` 中标注各轮对应的状态节点，确保对话流程符合 Reference Resources 中的标准状态转移路径
12. **基于标准链路构造**：多轮对话应基于 Reference Resources 中的标准转移链路设计。不得构造不存在的转移路径（如从 `FX_*` 跳过 `return_to_business` 直接到 `JK_*`，或从 `RG_*` 终态继续对话）。P0 全局规则除外（任意状态均可触发）
13. **case_desc 格式**：`[评测维度标签] 场景简述 状态链路:INIT→XX→XX→...`，其中评测维度标签为 A-上下文记忆/B-意图转移/C-上下文污染/D-合规底线/E-客诉控制/F-对话连贯性/G-信息一致性
14. **remark 标注状态**：每轮的 remark 中标注当前轮次对应的状态节点和评测关注点，格式如"状态进入TL_CQZX | 评测上下文记忆：模型是否引用前文额度信息"


## Supplementary Knowledge

**多轮对话常见评测难点：**
- 「上下文记忆」的最大挑战是用户使用代词（"那个"、"它"）或省略主语，模型需要从前文中推断指代
- 「意图转移」中最容易被误判的是用户在同一个大意图下切换小意图（如提额操作咨询→提额进度咨询），这不算漂移
- 「上下文污染」常出现在用户快速切换话题时，模型把前一个话题的术语/结论带入新话题
- 「信息一致性」中最常见的问题是数字单位混淆（元/万元）和利率表述差异（日利率/月利率/年利率）
- 客诉场景下，模型可能"安抚了但没有转人工"，这在评估中仍应判定为不通过

**标准话术风格参考：**
- 告知类话术：以"您好"开头，信息简洁明了，必要时使用分段
- 拒答类话术：以"抱歉"开头，明确说明拒绝原因，主动引导回正常业务
- 安抚类话术：先共情（"非常抱歉给您带来不便"），再提供解决方案，最后引导转人工
- 引导类话术：先告知现状（"您当前额度XXX"），再给出建议（"建议您XXX"），最后引导操作

- 实际生成时，standard_answer 必须根据标准知识文档和每个具体意图场景重新构造
- 切勿直接复用示例中的话术内容
