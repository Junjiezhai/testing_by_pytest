# 贷后催收会话状态转移矩阵

> **文档用途**：定义贷后催收场景下的完整会话状态机，用于对话管理系统（Dialogue Management System）的设计与实现。
>
> **核心目标**：引导用户还款；若无能力则进行协商（减免/停催/协商还款）。
>
> **关联文件**：
> - `docs/postloan_intent_taxonomy.md` — 贷后催收意图分类体系
> - `docs/postloan_ref_QA_intent.md` — 标准问答库（388条用例）
> - `model_skills/gen_postloan_single_round_cases.md` — 测试用例生成 Skill

---

## 1. 会话状态定义

### 1.1 状态编码规范

状态编码采用 **2字母业务域 + 2字母状态语义** 的格式：

- `CS` — 催收（CuiShou）
- `XH` — 协商（XieShang）
- `JM` — 减免（JianMian）
- `TY` — 停催/减压（TingCui/JianYa）
- `HK` — 还款（HuanKuan）
- `ZX` — 咨询（ZiXun）
- `RG` — 人工（RenGong）
- `FX` — 风险（FengXian）
- `MH` — 模糊（MoHu）
- `FY` — 非业务（FeiYeWu）
- `INIT` — 初始状态
- `END` — 结束状态

## 2. 状态转移矩阵

### 2.1 协商还款主流程状态转移

> **适用客群**：有一定还款能力，有还款意愿，希望重新制定还款计划。

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT`（初始） | 协商还咨询 | `ACT_YWJS` 业务知识介绍 | `XH_YWZX`（协商业务咨询态） |
| `XH_YWZX` | 协商还准入条件咨询 | `ACT_ZRTJ` 准入条件陈述 | `XH_ZRTJ`（资质确认态） |
| `XH_ZRTJ` | 协商还操作咨询 | `ACT_CQZY` 操作指引 | `XH_NLQR`（还款能力确认态） |
| `XH_NLQR` | 还款能力&意愿确认 | `ACT_NLQR` 还款能力确认 → 确认可承担还款金额 | `XH_KPZX`（卡片推送态） |
| `XH_KPZX` | 用户申请协商还款 | `ACT_TSKP` 推送协商还款卡片 | `XH_SQCL`（申请处理态） |
| `XH_SQCL` | 协商还进度查询 | `ACT_JDJG` 进度查询结果 | `XH_JDZX`（进度查询态） |
| `XH_JDZX` | 协商还结果查询 | `ACT_JGYZ` 结果告知 | `XH_JGZX`（结果查询态） |
| `XH_JGZX` | 审核通过 | `ACT_YDHK` 引导还款（按新方案） | `HK_FSCX`（引导至还款操作态） |
| `XH_JGZX` | 审核失败 | `ACT_AFYD` 安抚引导 → 重新评估 | `XH_NLQR`（回到还款能力确认态） |

### 2.2 还款减免主流程状态转移

> **适用客群**：有还款能力，无还款意愿（或还款意愿不强），希望结清出催。

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT`（初始） | 减免咨询 | `ACT_YWJS` 业务知识介绍 | `JM_YWZX`（减免业务咨询态） |
| `JM_YWZX` | 减免准入条件咨询 | `ACT_ZRTJ` 准入条件陈述 | `JM_ZRTJ`（资质确认态） |
| `JM_ZRTJ` | 减免操作咨询 | `ACT_CQZY` 操作指引 | `JM_NLQR`（还款能力确认态） |
| `JM_NLQR` | 还款能力确认 | `ACT_NLQR` 还款能力确认 → 确认可结清金额 | `JM_KPZX`（卡片推送态） |
| `JM_KPZX` | 用户申请减免 | `ACT_TSKP` 推送减免方案卡片 | `JM_SQCL`（申请处理态） |
| `JM_SQCL` | 减免进度查询 | `ACT_JDJG` 进度查询结果 | `JM_JDZX`（进度查询态） |
| `JM_JDZX` | 减免结果查询 | `ACT_JGYZ` 结果告知 | `JM_JGZX`（结果查询态） |
| `JM_JGZX` | 审核通过 | `ACT_YDHK` 引导还款（按减免后金额） | `HK_FSCX`（引导至还款操作态） |
| `JM_JGZX` | 审核失败 | `ACT_AFYD` 安抚引导 → 引导协商还款 | `XH_NLQR`（引导至协商还款态） |

### 2.3 还款减压（停催）主流程状态转移

> **适用客群**：无还款能力，有还款意愿，希望停止催收、延期还款。

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT`（初始） | 停催咨询 | `ACT_YWJS` 业务知识介绍 | `TY_YWZX`（停催业务咨询态） |
| `TY_YWZX` | 停催咨询，系统推送协商还卡片（分支A：推荐协商还） | `ACT_TSKP` 推送协商还卡片 | `TY_XSKP`（协商还卡片推送态） |
| `TY_XSKP` | 用户确认不办理协商还服务，进入停催流程 | `ACT_YYQR` 原因确认 → 引导用户说明困难原因 | `TY_YYQR`（原因确认态） |

| `TY_TSQR` | 符合条件，用户申请停催 | `ACT_TSKP` 推送停催方案卡片 | `TY_KPZX`（卡片推送态） |
| `TY_KPZX` | 停催申请处理 | `ACT_CQZY` 操作指引 → 引导提交申请 | `TY_SQCL`（申请处理态） |
| `TY_SQCL` | 停催进度查询 | `ACT_JDJG` 进度查询结果 | `TY_JDZX`（进度查询态） |
| `TY_JDZX` | 停催结果查询 | `ACT_JGYZ` 结果告知 | `TY_JGZX`（结果查询态） |
| `TY_JGZX` | 审核通过 | `ACT_YDHK` 引导按新计划还款 | `HK_FSCX`（引导至还款操作态） |
| `TY_JGZX` | 审核失败 | `ACT_AFYD` 安抚引导 → 引导协商还款 | `XH_NLQR`（引导至协商还款态） |

### 2.4 还款咨询流程状态转移

> **核心目标**：引导用户尽快完成还款。

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT`（初始） | 还款方式查询 | `ACT_CQZY` 操作指引 | `HK_FSCX`（还款方式查询态） |
| `INIT`（初始） | 还款金额查询 | `ACT_JDJG` 查询结果 → 告知应还金额 | `HK_JECX`（还款金额查询态） |
| `HK_FSCX` / `HK_JECX` | 用户有还款意向 | `ACT_YDHK` 引导还款 → 推送还款链接 | `HK_YDTS`（引导还款推送态） |
| `HK_YDTS` | 用户完成还款 | `ACT_JGYZ` 结果告知 → 确认还款成功 | `END`（结束状态） |
| `HK_YDTS` | 用户表示无法还款 | `ACT_AFYD` 安抚引导 → 了解原因 | `TY_YYQR`（引导至停催原因确认态） |
| `HK_YDTS` | 用户询问减免/协商 | `ACT_YWJS` 业务知识介绍 | `JM_YWZX` / `XH_YWZX`（引导至减免/协商态） |

### 2.7 异常处理流程状态转移

> **全局规则**：以下 P0 级转移适用于**所有状态**，即用户在任何业务状态下识别到以下意图时，应立即触发对应转移，无需等待当前业务流程完成。

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT` / **任意状态** | 违规操作 | `ACT_FXJJ` 风险拒绝 | `FX_WGCZ`（风险拒绝态）→ `END` |
| `INIT` / **任意状态** | 内部信息探知 | `ACT_FXJJ` 风险拒绝 | `FX_NBXX`（风险拒绝态）→ `END` |
| `INIT` / **任意状态** | 用户主动要求转人工 | `ACT_RGFW` 转人工 | `RG_BZSQ`（标准转接态）→ `END` |
| `INIT` / **任意状态** | 用户情绪升级/投诉 | `ACT_AFYD` 安抚引导 + `ACT_RGFW` 转人工 | `RG_QXSJ`（情绪处理态）→ `END` |
| `INIT` / **任意状态** | 模型无法完全理解用户意图 | `ACT_FWCL` 反问澄清 | `MH_FWCL`（反问澄清态）→ 等待用户澄清后回原状态或 `INIT` |
| `INIT` / **任意状态** | 用户输入过于模糊/信息缺失 | `ACT_MHZD` 模糊引导 | `INIT`（回到初始，等待补充信息） |
| `INIT` / **任意状态** | 非业务相关/闲聊 | `ACT_LTXZ` 闲聊引导 | `INIT`（回到初始，等待业务问题） |

#### 2.7.1 转人工全局规则详解

转人工是贷后催收场景中**最高优先级**的全局转移，尤其当用户表达投诉、不满情绪时，必须立即触发。以下是具体场景示例：

| 业务场景 | 当前状态 | 触发条件 | 转移动作 |
|---------|---------|---------|---------|
| 协商流程中用户不耐烦 | `XH_NLQR` | 用户说"太麻烦了，快给我转人工" | `ACT_AFYD` + `ACT_RGFW` → `RG_QXSJ` |
| 减免流程中用户主动要求 | `JM_ZRTJ` | 用户说"帮我转人工客服" | `ACT_RGFW` → `RG_BZSQ` |
| 停催流程中情绪升级 | `TY_CHZS` | 用户说"你们催收太频繁了，我要投诉" | `ACT_AFYD` + `ACT_RGFW` → `RG_QXSJ` |
| 还款咨询中强烈不满 | `HK_JECX` | 用户说"你们怎么又打电话，我要投诉" | `ACT_AFYD` + `ACT_RGFW` → `RG_QXSJ` |

#### 2.7.2 反问澄清与模糊引导的区别

| 维度 | `ACT_FWCL` 反问澄清 | `ACT_MHZD` 模糊引导 |
|------|-------------------|-------------------|
| 触发条件 | 模型能听懂问题但**不完全理解**用户意图（如用户说"能不能商量下"无法确定是协商还是减免） | 用户输入**严重缺失关键信息**（如只有语气词、短语不成句） |
| 系统行为 | **主动提出具体澄清问题**，如："您是想申请协商还款还是减免呢？" | **引导用户补充信息**，如："请问您具体遇到了什么困难？" |
| 下一状态 | `MH_FWCL`（反问澄清态）→ 用户澄清后回到原业务状态 | `INIT`（初始态）→ 等待用户重新发起完整问题 |
| 用户体验 | 对话有延续性，模型展示理解尝试 | 对话重新开始，更接近"听不懂，请再说一遍" |

## 5. 实现建议

### 5.1 状态机实现要点

1. **状态持久化**：每次用户提问后，系统应根据识别到的意图，查询当前状态对应的转移规则，确定下一状态和应答动作。状态应持久化存储，支持多轮对话上下文。

2. **上下文管理**：会话状态应包含：
   - 当前状态编码
   - 历史状态栈
   - 已收集的用户信息（如还款能力、困难原因、协商金额等）
   - 会话轮次计数
   - 用户情绪标签（正常/焦虑/愤怒等）

3. **超时处理**：长时间未响应的会话应自动重置到 `INIT` 状态。建议设置会话超时时间为 30 分钟。

4. **催收特殊处理**：
   - **催收敏感词过滤**：用户提及"投诉"、"举报"、"报警"等敏感词时，立即触发情绪评估
   - **还款引导时机**：在解答任何业务问题后，系统应主动引导还款（"您可以点击以下链接进行还款"）
   - **协商失败兜底**：减免/停催失败后，应主动引导用户尝试协商还款方案，而非直接结束对话

### 5.2 核心业务流程闭环策略

1. **协商还款闭环**：
   - 用户表达还款困难 → 引导协商还款 → 确认还款能力 → 推送方案 → 用户申请 → 进度跟踪 → 结果反馈 → 按新方案还款

2. **还款减免闭环**：
   - 用户请求减免 → 确认准入条件 → 确认还款能力 → 推送减免方案 → 用户申请 → 进度跟踪 → 结果反馈 → 按减免金额还款

3. **还款减压（停催）闭环**：
   - 用户请求停催 → 确认困难原因 → 收集困难陈述 → 确认还款意愿 → 资质确认 → 推送停催方案 → 用户申请 → 进度跟踪 → 结果反馈 → 按新计划还款

4. **引导还款闭环**：
   - 任何咨询结束后 → 主动引导还款 → 提供还款链接 → 确认还款成功

### 5.3 异常兜底策略

1. **全局异常捕获**：任何状态下都应支持 P0 级别的异常转移（转人工、风险拒绝）。

2. **转人工兜底**：连续 N 次反问澄清或状态转移失败后，自动建议转人工。在贷后场景中，建议 N=2（比一般场景更敏感）。

3. **反问降级**：反问澄清后用户仍无法清晰表达时，降级为 `ACT_MHZD` 模糊引导。

4. **情绪感知**：任意业务状态下需持续监测用户情绪信号，一旦识别到不满/愤怒/焦躁等，应立即触发安抚引导并评估是否需要转人工。贷后场景中情绪升级是 P0 级事件。

5. **协商失败兜底**：减免/停催申请失败后，系统应主动推荐协商还款方案（"您的减免申请未通过，但我们可以为您制定分期还款计划"），而非简单告知失败。

### 5.4 主动引导策略

1. **咨询后主动引导还款**：用户咨询还款方式/金额/征信等问题后，系统应主动推送还款链接，不应等待用户明确表达还款意向。

2. **协商成功后引导还款**：协商/减免/停催方案审核通过后，系统应主动引导用户按新方案还款（"方案已生效，请点击以下链接完成本期还款"）。

3. **引导话术个性化**：
   - 逾期天数较短（<30天）："建议您尽快还款，避免逾期影响征信"
   - 逾期天数较长（30-90天）："我们可以为您申请减免/协商还款方案"
   - 逾期天数很长（>90天）："建议您尽快处理，我们可以为您制定分期还款计划"

4. **交叉引导**：
   - 减免失败后 → 引导协商还款
   - 停催失败后 → 引导协商还款
   - 协商还款无力承担 → 引导停催

### 5.5 反问澄清策略

1. **触发判断**：当意图识别置信度低于阈值（建议 0.7）或识别到多个意图且无法确定优先级时，触发反问澄清。

2. **反问内容**：反问应具体、有指向性，贷后场景示例：
   - "您是想申请减免费用，还是协商分期还款呢？"
   - "您是指暂时无力还款想申请停催，还是想协商新的还款计划呢？"
   - "您咨询的是本期应还金额，还是想申请减免后的金额呢？"

3. **反问次数限制**：单轮会话中反问次数不超过 2 次，超过后自动建议转人工。
